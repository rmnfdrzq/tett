# Интерактивная форма заказа керамической плитки

Веб-приложение на базе **Next.js**, **Redux Toolkit** и **Tailwind CSS**, представляющее собой интерактивную форму заказа керамической плитки. Данное риложение выполнено в соответствии с текстом [тестового задания](https://gitlab.com/tile-expert-test-tasks/frontend).

Приложение размещено на Vercel и доступно по адресу: https://tett-gules.vercel.app/

---

## Основные возможности

### 1. Интерактивная корзина покупок

- **Управление количеством**: изменение площади покрытия (в кв. футах) с помощью интуитивных кнопок `+` / `-` или прямого ввода.
- **Динамический выбор**: добавление новых видов плитки в корзину из выпадающего каталога с мгновенной анимацией появления.
- **Удаление позиций**: возможность удаления отдельных позиций с каскадным обновлением связанных компонентов.

### 2. Интерактивный конфигуратор «Visualize Your Order» (Drag & Drop)

- **Сетка 6x6**: интерактивное поле для визуализации будущей раскладки плитки.
- **Палитра дизайна (Design Palate)**: отображает образцы плитки, находящиеся в корзине в данный момент. Мгновенно синхронизируется с корзиной.
- **Синхронное поведение**:
  1. В визуализаторе и палитре отображаются _только_ те плитки, которые добавлены в корзину.
  2. При добавлении нового вида в корзину плитка мгновенно появляется в палитре.
  3. При полном удалении позиции из корзины все её образцы автоматически удаляются как из палитры, так и со всей сетки визуализатора.
- **Перемещение плитки**:
  - Drag-and-drop (перетаскивание) плиток из палитры в ячейки сетки.
  - Перетаскивание плиток между ячейками сетки.
- **Удаление плитки из сетки**:
  - _Двойной клик_ по плитке в сетке для ее удаления.
- **Стартовое состояние**: по умолчанию сетка предзаполнена четырьмя плитками из корзины на позициях: 1-й и 2-й столбцы первой строки (Ocean Wave, Forest Fern) и 1-й и 2-й столбцы второй строки (Terracotta Dot, Yellow Star).

### 3. Форма оформления заказа и оплаты

- **Способы оплаты**: поддержка карт Visa/Mastercard, Apple Pay, PayPal и прямого банковского перевода с премиальным дизайном чекбоксов.
- **Валидация полей**: встроенная строгая проверка имени клиента, телефона, email, адреса доставки, номера карты, срока действия (в формате MM/YY) и CVV-кода.
- **Адаптивные плейсхолдеры**: пропорциональное уменьшение числовых символов в поле номера карты для идеального баланса с текстовыми полями.

### 4. Бизнес-логика расчетов

- **Subtotal**: сумма произведений количества (в кв. футах) на цену за единицу для всех позиций в корзине.
- **Shipping**: если `Subtotal > $500.00`, доставка осуществляется **Бесплатно ($0.00)**, иначе — **$25.00**. Если корзина полностью пуста (`Subtotal = $0.00`), доставка автоматически равна **$0.00**.
- **Grand Total**: сумма `Subtotal` и `Shipping`.

### 5. Адаптивная верстка (Responsive Realignment)

- **Десктопный режим (>1200px)**:
  - Трёхколоночная сетка со сбалансированными пропорциями.
  - Боковые декоративные SVG-крылья, обрамляющие заголовок.
  - Эффектные двойные рамки ("чернильный" бруталистский контур), стилизованные фоны и отсутствие теней на элементах оплаты.
  - Эстетическое вертикальное вытягивание шрифтов заголовков и итогов на 15-20% (`scaleY`) для премиального бруталистского стиля.
- **Переходный режим (1200px и менее)**:
  - При ширине экрана 1200px и ниже интерфейс **полностью переключается на мобильную версию**, обеспечивая безупречный UX на планшетах и смартфонах.
  - Боковые декоративные иконки скрываются.
  - В шапке в верхнем фиксированном Nav Bar отображаются **только кнопки SHOP, COLLECTIONS, ABOUT US**.
  - Размеры шрифтов заголовков уменьшаются до **`24px`** и **`16px`**, чтобы полностью умещаться по ширине.
  - Все элементы fixed-панели (высота, ссылки, иконка корзины, кнопка Log In и миниатюрные шевроны плиток размером **`18px`**) пропорционально уменьшаются.
  - **Динамическое сжатие таблицы**: для предотвращения горизонтального переполнения, в строках `tbody` размер шрифта уменьшается до `11.5px`, а межсимвольный интервал — до `-0.05em`.

## 6. Технический стек

- **Фреймворк**: [Next.js 16 (App Router)](https://nextjs.org/) на базе **React 19**
- **Язык**: [TypeScript](https://www.typescriptlang.org/) с высокой типизацией
- **Стейт-менеджер**: [Redux Toolkit](https://redux-toolkit.js.org/) для глобального реактивного состояния корзины и визуализатора
- **Интерактивная сетка**: [@dnd-kit/core](https://dnd-kit.com/) для плавного drag-and-drop
- **Стилизация**: [Tailwind CSS v4](https://tailwindcss.com/)
- **Анимации**: [Framer Motion](https://www.framer.com/motion/) для плавного появления/исчезновения строк в таблице, карточек в палитре и анимации бейджа корзины (`badge-pop`)
- **Тестирование**: [Vitest](https://vitest.dev/) для модульного тестирования логики расчетов, валидации и слайсов Redux

## Инструкция по запуску

### 1. Установка зависимостей

Установите все необходимые npm-пакеты:

```bash
npm install
```

### 2. Запуск в режиме разработки

Запустите локальный сервер разработки:

```bash
npm run dev
```

После запуска откройте в браузере [http://localhost:3000](http://localhost:3000).

### 3. Запуск юнит-тестов

Запуск полного пакета модульных тестов в среде Vitest (включает валидацию, расчеты и работу Redux slices):

```bash
npm test
```

### 4. Создание продакшн-сборки

Для компиляции оптимизированного продакшн-бандла выполните:

```bash
npm run build
```

Сборка полностью валидирует код компилятором TypeScript, проверяет отсутствие ошибок SSR и генерирует оптимизированные статические страницы.

## Пояснения

Так как дизайн-макеты в тестовом заднии явно сгенерированы нейронкой, в них прослеживаются некоторые нарушения UX/UI принципов, а так же фактические расхождения с ТЗ. Хотя я и постарался максимально придерживаться pixel-perfect подхода, при выполнении задания я все же допустил некоторые отклонения от макетов/ТЗ:

- Сетка в визуализатор-блоке сделана 6х6 в соответствии с текстом задания, а не 7х6 и без скролл-баров, как на макете;
- Некоторые отступы между блоками специально изменены для поддержания конситентности дизайна и лучшей адаптивности;
- На макете моковые Subtotal и Grand Total рассчитаны не правильно, поэтому я использовал не их, а реальные рассчеты из предоставленной формулы;
- При рассчеты стоимости доставки не указано, что должно быть в Shipping при Subtotal = 0, поэтому в таком случае я сделал Shipping тоже равным 0;
- В ТЗ явно указано требование про наличие кнопок для изменения quantity товара, а так же про удаление всей позиции из корзины - для этого я добавил отдельную кнопку delete, так как это повышает качестве UX в случаях, когда quantity слишком большой (сотню раз нажимать на "минус" попросту неудобно);
- Все декоративные элементы векторизованы и сохранены отдельными файлами;
- Все плитки нарезаны из макетов на отдельные PNG файлы;
- Декоративные элементы по краям страниц я специально разделил на части для лучшей адаптивности.
